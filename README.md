# GeoCoral — ResNet50 Coral Bleaching Classifier (Training Pipeline)

Model-training component of *GeoCoral: A ResNet50-Based Coral Bleaching
Assessment and Geomapping Application for Marine Sanctuaries in Samal
Island, Davao Gulf*. Implements the Methodology chapter exactly:
CLAHE + resize + ImageNet-normalize preprocessing, train-only
augmentation, a two-phase ResNet50 transfer-learning strategy, and
accuracy/precision/recall/F1 evaluation.

## 1. Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Add your data

**Local field images** (from Samal Island sanctuary surveys) go in:

```
raw_data/local_field_images/
├── healthy/       <- .jpg/.png images
├── bleached/       <- .jpg/.png images
└── metadata.csv    <- one row per filename (see metadata_template.csv)
```

Copy `metadata_template.csv` to `metadata.csv` and fill in one row per
image: `filename, label, latitude, longitude, datetime, depth_m,
sanctuary_location, area_code, photographer`.

**Faster option:** if your photos have embedded GPS/EXIF data (most
phones and GPS-enabled cameras do), run this instead of typing
coordinates in by hand. Put your photos straight into
`healthy/`/`bleached/`, then run one command per dive session:

```bash
python -m data_prep.extract_metadata \
    --depth 5.2 \
    --sanctuary "Adecor Marine Sanctuary" \
    --area-code ADE-01 \
    --photographer "J. Dela Cruz"
```

This reads latitude/longitude/timestamp straight from each photo's
EXIF data and writes `metadata.csv` for you — you only type in the
values that stay constant for the whole dive (depth, sanctuary, area
code, photographer). Photos with no embedded GPS are still added, with
blank coordinates, and the script prints their filenames so you know
which ones need manual entry. Safe to re-run as you add more photos —
it won't duplicate existing rows.

**Kaggle supplementary dataset** ("Bleached and Unbleached Corals
Classification" by sonainjamil) goes in:

```
raw_data/kaggle_bleached_corals/
├── healthy/
└── bleached/
```

Download it from Kaggle and sort images into these two folders (the
Kaggle download ships as bleached/unbleached folders — rename
`unbleached` to `healthy` to match this project's class names).

## 3. Build the processed dataset (CLAHE + resize + stratified 70/15/15 split)

```bash
python -m data_prep.prepare_dataset
```

Produces `processed_data/{train,val,test}/{healthy,bleached}/` and
`processed_data/split_metadata.csv` (carries GPS/field metadata through
to the split images, for the app's geomapping layer later).

## 4. Train the model

```bash
python -m training.train
```

Runs Phase 1 (head-only, base frozen, LR 1e-4) then Phase 2
(fine-tune `conv5_block*`, LR 1e-5), each with early stopping and
checkpointing on `val_loss`. Outputs:

- `saved_models/geocoral_resnet50_best.keras` — best checkpoint
- `saved_models/geocoral_resnet50_final.keras` — final model
- `logs/` — per-phase CSV logs + TensorBoard logs + combined history JSON

## 5. Evaluate on the held-out test set

```bash
python -m training.evaluate
```

Prints accuracy, precision, recall, F1-score, and a confusion matrix.

## 6. Run inference on a single image (for Django integration)

```bash
python -m training.predict path/to/photo.jpg
```

Or import `training.predict.predict()` directly from the Django upload
view — pair its returned label with the photo's submitted GPS
coordinates before writing the record to PostgreSQL/PostGIS for the
geomapping interface.

## Project structure

```
config.py                    Central config: paths, split ratios, hyperparameters
data_prep/prepare_dataset.py CLAHE + resize + stratified split
data_prep/extract_metadata.py EXIF-based GPS/timestamp auto-fill for metadata.csv
training/dataset.py          tf.data pipeline (ImageNet normalize, train-only augment)
training/model.py            ResNet50 + custom head, freeze/unfreeze helpers
training/train.py            Two-phase training loop
training/evaluate.py         Test-set metrics
training/predict.py          Single-image inference
raw_data/                    Your input images + metadata go here (not tracked)
processed_data/              Generated by prepare_dataset.py
saved_models/, logs/         Generated by train.py
backend/                     Django + GeoDjango + DRF backend — see backend/README.md
```

## Notes

- The Kaggle dataset's images are used for training only — they have
  no field GPS data and are excluded from the geomapping interface
  (`source` column in `split_metadata.csv` distinguishes them from
  `local_field` images).
- Because the Kaggle images come from a different reef system (Great
  Barrier Reef) than Samal Island, treat this as a starting point:
  the more local field images you add, the better the model should
  generalize to your actual survey conditions and coral species — this
  is worth naming explicitly as a limitation in your paper.

## Backend / full application

Once you have a trained model, `backend/` contains the Django +
GeoDjango + DRF API that stores GPS-tagged classification results and
serves them for the geomapping interface. It calls this project's
`training/predict.py` directly for inference. See `backend/README.md`
for setup.
